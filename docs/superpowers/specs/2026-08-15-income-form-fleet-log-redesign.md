# Редизайн формы дохода, учёта техники и диаграммы "Расходы/Доходы"

## Контекст

Текущая форма дохода классифицирует запись по тому, ЧТО было продано (Техника/Прочее/Предоплата). Способ оплаты (Нал/Безнал/Сертификат) указывается отдельным полем только для режима "Прочее" — то есть для основного потока дохода (аренда техники) способ оплаты вообще не фиксировался.

Цель редизайна — перевернуть логику: классифицировать доход по способу оплаты (Наличные/Безнал/Прочее), а учёт техники (сколько единиц какого вида уехало) вынести в отдельный лог, не привязанный к деньгам — по образцу уже существующей панели "Источник" (`sourceRecords`).

## Согласованные решения

- Режим "Предоплата" убирается полностью (поля клиента и суммы предоплаты, отдельная категория "Предоплата").
- Раздел "Прочее" в новой форме дохода — только текстовое поле категории + сумма, без способа оплаты и без клиента.
- Учёт техники полностью убирается из формы дохода и переезжает в отдельный независимый лог (без суммы), по образцу "Источника".
- Старые записи (тестовая "Питбайк ×1", исторические "Старые записи") не мигрируются и не переносятся в новый лог техники — это осознанно, лог техники просто стартует пустым.
- Расходная часть (категории ГСМ/Реклама/Аренда/ЗП работника/Запчасти, партнёры ДОК/ГЛ) не меняется.
- Панель "Источник" не меняется — она использовалась только как образец паттерна для копирования.

## Изменения в форме дохода (`entryForm`)

Переключатель `income-cat-toggle` меняет 3 кнопки с `data-icat="technika"/"other"/"prepay"` на `data-icat="cash"/"noncash"/"other"` (Наличные/Безнал/Прочее):

- **Наличные** (`cash`): только поле суммы. При отправке `category: 'Наличные'`.
- **Безнал** (`noncash`): только поле суммы. При отправке `category: 'Безнал'`.
- **Прочее** (`other`): текстовое поле категории (`fOtherCategory`, уже существует) + поле суммы. При отправке `category: <введённый текст>`.

Убирается из разметки и JS:
- Блок выбора техники (`technikaItemsWrap`, `technikaItemsList`, `addTechnikaItemBtn`) и вся связанная логика (`createTechnikaItemRow`, `resetTechnikaItems`, `refreshTechnikaItemSelects`).
- Дропдаун способа оплаты (`fPaymentGroup`, `fPayment`, `fPaymentManualWrap`, `fPaymentManual`) — был нужен только старому режиму "Прочее".
- Поля клиента и предоплаты (`fClientWrap`, `fClient`, `fPrepaymentWrap`, `fPrepayment`) и ветка `incomeCategoryMode === 'prepay'` в обработчике submit.

Записи дохода, создаваемые новой формой, имеют вид:
```js
{
  date, type:'income', status:'completed',
  category: 'Наличные' | 'Безнал' | <текст>,
  amount: Number,
  qty: 0, payment:'', source:'', client:'', prepayment:0,
  createdAt: Date.now()
}
```
Поля `qty`/`payment`/`source`/`client`/`prepayment` остаются пустыми плейсхолдерами ради совместимости со старыми записями и общим кодом рендера/CSV-экспорта, который их читает.

`state.paymentMethods` (настройка Нал/Безнал/Сертификат) перестаёт использоваться в UI — не удаляется из `settings/config` в Firestore (безвредные неиспользуемые данные), просто больше не читается формой.

## Новый лог техники

Новая коллекция Firestore `fleetRecords`, структурно идентичная `sourceRecords`:
```js
{ date, equipmentType, qty, createdAt }
```

В шапке панели "Учет проката техники" добавляется кнопка "+" (`openFleetModalBtn`), аналогичная `openSourceModalBtn`. Открывает модалку `fleetModalOverlay`:
- Поле даты
- Повторяемые строки: селект вида техники (источник списка — `state.equipmentTypes`, с опцией "Заполнить вручную", как у источника) + количество
- Кнопка "+ Добавить технику" (аналог "+ Добавить источник")
- Сабмит → `writeBatch` создаёт документ в `fleetRecords` на каждую строку (аналогично тому, как `sourceForm` сейчас пишет в `sourceRecords`).

Функции `createFleetItemRow`, `resetFleetItems`, `refreshFleetItemSelects`, `openFleetModal`, `closeFleetModal` — прямые аналоги одноимённых функций для источника (`createSourceItemRow` и т.д.), с заменой `si-*` классов на `fi-*` и `state.sources`/`sourceRecordsCol` на `state.equipmentTypes`/`fleetRecordsCol`.

## Диаграмма техники (`chartFleet` / `fleetList`)

Полностью переписывается на тот же паттерн, что уже использует диаграмма источника (`chartSource`/`sourceList`):
- `getFilteredFleetRecords()` — копия `getFilteredSourceRecords()`, фильтрует `state.fleetRecords` по текущему периоду (месяц/диапазон).
- Группировка по `equipmentType`: если входит в `CORE_FLEET_TYPES` — своя корзина, иначе — "Прочее" с раскрывающимся списком (детали по `otherFleetDetails`).
- Убирается текущая логика вычисления `fleetByType` из `incomeTx`/`items`.

`state.fleetRecords` наполняется через `onSnapshot(fleetRecordsCol, ...)` — так же, как `state.sourceRecords`, добавляется в `startFirestoreSync()`/`stopFirestoreSync()` (ещё один `unsubscribers.push(...)`).

## Диаграмма "Расходы/Доходы" (`chartOverview`)

Доходная часть перегруппировывается: вместо эвристики "есть `items` или `category` из `CORE_FLEET_TYPES` → Техника, иначе → Прочее" используется прямое сравнение категории со списком:
```js
const CORE_INCOME_CATEGORIES = ['Наличные', 'Безнал'];
```
Категория входит в список → своя корзина (Наличные/Безнал), не входит (включая старые "Питбайк ×1", "Старые записи", любой будущий текст "Прочее") → корзина "Прочее" с раскрывающимся списком по фактическим категориям (`otherIncomeDetails`) — механизм раскрывающегося списка уже существует в коде, меняется только условие группировки.

Расходная часть диаграммы не меняется.

## Совместимость со старыми данными

- Старые доходные записи (тестовая, "Старые записи") не удаляются и не мигрируются — просто отображаются в бакете "Прочее" на диаграмме доходов, с реальной категорией видной в раскрывающемся списке.
- Лог техники (`fleetRecords`) стартует пустым — старые количества техники в него не переносятся (осознанное решение, подтверждено пользователем).
- Экспорт CSV не меняется структурно (те же колонки), просто новые записи будут иметь другие значения в колонке "Категория".

## Вне скоупа

- Миграция/перенос старых записей о технике в новый лог.
- Изменения на стороне расходов.
- Изменения панели "Источник".
